# Frontend Worker — Five-Page Sequential Delivery

1. Read `sdocs/FRONTEND_PAGE_BUILD_PLAYBOOK.md`, `sdocs/FRONTEND_BUILD_PROGRESS.json`, `sdocs/IMAGE_REFERENCE_GUIDE.md`, `sdocs/TASK_QUEUE.json`, and `sdocs/schema-contract.md` before coding. The playbook and approved master specification govern page order and requirements.
2. Work only on the frontend task the Orchestrator marked `in_progress`. Increment its `attempts` exactly once, clear its previous error, and remove its matching retry record. Never self-assign if no task is assigned.
3. Build up to FIVE complete consecutive page destinations in this 10-minute cycle. Five is the maximum target, not a quota: build fewer if needed to keep pages complete, secure, functional, and passing checks. Start with the global application shell/header, top-level menu, first workspace submenu and its destinations; then proceed to the next workspace and its submenu destinations in the exact approved order. Do not jump ahead or invent pages.
4. Use `sdocs/FRONTEND_BUILD_PROGRESS.json` as the sequence cursor. Advance it only for destinations actually implemented and checked. Record exact page names and route paths in the task diagnostics/cycle report. Do not mark a page complete merely because a route or placeholder renders.
5. Each page must satisfy every applicable requirement in `sdocs/FRONTEND_PAGE_BUILD_PLAYBOOK.md`: responsive shell, title/breadcrumb/context, role/tenant-aware data, contract-backed queries/mutations, real actions, validation, and loading/empty/success/error/denied/disconnected/stale states. Collections need authorized search/filter/sort/pagination as relevant; record details need ownership/status/timestamps/audit data as authorized.
6. Use only tables, RPCs, and Edge Functions documented in `sdocs/schema-contract.md`. Never invent endpoints, fake data as live, show fake success, create dead buttons, or make browser-side security/reward decisions. If a backend contract is missing, document the exact blocker for the Orchestrator/Supabase worker.
7. For page visuals, follow `sdocs/IMAGE_REFERENCE_GUIDE.md` and insert `<img src="/images/placeholder.png" data-prompt="specific descriptive visual prompt" alt="meaningful alt text" />`. Do not point to missing files or change the reference master images.
8. Update only the assigned task's `files_changed` with actual repository-relative paths and set it to `needs_verification` only when the contiguous slice is ready for independent audit. Never set `verified`, update verified counts, percentages, or overall status.
9. If the slice is incomplete or blocked, send the task to `retry_queue` with precise diagnostics and actionable next steps. Report exactly which destinations were completed, which were not, and why.
