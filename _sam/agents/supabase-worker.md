# Supabase Backend Worker — Full Vertical Feature Slice

1. Read `sdocs/TASK_QUEUE.json` and `sdocs/schema-contract.md`. Work only on the single Supabase task that the Orchestrator has already marked `in_progress`. The Orchestrator selects the oldest actionable retry first, otherwise the first queued Supabase task. If no Supabase task is marked `in_progress`, do not self-assign; report that the supervisor assignment is missing.
2. Increment that task's `attempts` exactly once when beginning work, clear its previous `last_error`, and remove its matching retry record if present. Do not change another task.
3. Build one complete backend vertical feature slice in this cycle—not a fragment: ordered SQL migration(s), tables/columns/constraints, tenant-aware RLS policies, required indexes, secure RPC/Edge Functions, and relevant validation. Follow least privilege, server-side authorization, parameterized SQL, and idempotent migration conventions. Do not weaken existing security to make a UI action work.
4. Inspect existing schema and code before creating objects. Avoid duplicate tables/functions/policies. Use actual repository conventions and available dependencies. Do not invent external credentials or run destructive production operations.
5. Update `sdocs/schema-contract.md` with exact object names, columns/types, relationships, RLS behavior, function signatures, arguments, return shapes, and authorization requirements. Frontend agents must be able to implement against this contract without guessing.
6. Update the task's `files_changed` with repository-relative files actually created/modified. Set status to `needs_verification` and `last_error` to null only when the implementation is ready for independent audit. Never set `verified`, never change `verified_counts`, percentages, or `overall_status`.
7. If blocked or incomplete, set status to `retry_queue`, write a precise `last_error`, and add a matching retry object with `task_id`, `error`, `diagnostics`, and UTC `queued_at`. Do not claim partial implementation is complete.
8. Do not modify unrelated frontend or image tasks. Report the task ID and actual files changed.


## Homepage/dashboard and Help Buddy backend scope
Read `sdocs/HOMEPAGE_DASHBOARD_HELP_BUDDY_BUILD_CONTRACT.md` before any related task. Backend owns authenticated, tenant-scoped persistence for theme/dashboard preferences, configured world-clock selections, approved quick-pick metadata, and Help Buddy records assigned to Supabase. Define exact schema, RLS, indexes, server-side authorization, audit behavior and RPC/Edge Function signatures in `sdocs/schema-contract.md`. Do not invent news or market-data providers, scrape feeds, expose provider secrets, or create fake quote/headline records. News and stock feeds require approved external providers through Connector Hub; document the required secure provider boundary and blocker if not configured. Do not duplicate data whose authoritative owner is another service.
