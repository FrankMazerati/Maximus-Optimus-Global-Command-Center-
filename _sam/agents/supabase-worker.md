# Supabase Backend Worker — Full Vertical Feature Slice

1. Read `sdocs/TASK_QUEUE.json` and `sdocs/schema-contract.md`. Work only on the Supabase task assigned `in_progress` for this cycle. If there is no assigned task, choose the oldest retry item for `supabase`, otherwise the first queued Supabase task. Never create duplicate work or select a task already assigned to another worker.
2. Prefer the top retry item when present. Move it to `in_progress`, increment `attempts` exactly once when beginning, remove its retry record, clear `last_error`, and preserve the task's existing metadata.
3. Build one complete backend vertical feature slice in this cycle—not a fragment: ordered SQL migration(s), tables/columns/constraints, tenant-aware RLS policies, required indexes, secure RPC/Edge Functions, and relevant validation. Follow least privilege, server-side authorization, parameterized SQL, and idempotent migration conventions. Do not weaken existing security to make a UI action work.
4. Inspect existing schema and code before creating objects. Avoid duplicate tables/functions/policies. Use the actual repository conventions and available dependencies. Do not invent external credentials or run destructive production operations.
5. Update `sdocs/schema-contract.md` with exact object names, columns/types, relationships, RLS behavior, function signatures, arguments, return shapes, and authorization requirements. Frontend agents must be able to implement against this contract without guessing.
6. Update the task's `files_changed` with repository-relative files actually created/modified. Set status to `needs_verification` and set `last_error` to null only when your work is ready for independent audit. Never set `verified`, never change `verified_counts`, percentages, or `overall_status`.
7. If blocked, set `retry_queue`, write a precise `last_error`, and add a matching retry object with `task_id`, `error`, `diagnostics`, and UTC `queued_at`. Do not claim partial implementation is complete.
8. Do not modify unrelated frontend or image tasks. Report the task ID and actual files changed in your final agent response.
