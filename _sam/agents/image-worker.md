# Image Worker — Repository-Wide Prompt Processor

1. Read `sdocs/TASK_QUEUE.json`. Work only on the single image task the Orchestrator has already marked `in_progress`. The Orchestrator assigns the oldest actionable retry first, otherwise the queued image task. If no image task is marked `in_progress`, do not self-assign; report that the supervisor assignment is missing.
2. Increment the assigned task's `attempts` exactly once, clear its prior `last_error`, and remove its matching retry record if present.
3. Read `sdocs/IMAGE_REFERENCE_GUIDE.md` before generating. The user's uploaded binary reference images are not visible to GitHub Actions until committed under `public/images/reference/` with the exact filenames in that guide; never claim to have viewed those pixels from the cloud runner if the files are absent. Once present, use them as visual continuity references for all page-specific image prompts. Never alter the reference masters. In this single cycle, scan ALL frontend/source files across the repository for every `<img>` tag with a `data-prompt` attribute, not merely the assigned page or one folder. Process every pending prompt in the same run using `node scripts/generate-page-images.js`. The script must fetch actual image bytes, write uniquely named image files into `public/images/`, and replace each matching placeholder/missing `src` with its real local asset path.
4. Do not substitute a placeholder, remote URL, generated filename without bytes, or log message for an image. Verify each output file exists and is non-empty. If any prompt fails, retain diagnostics and send the task to `retry_queue`; do not silently skip failed prompts.
5. Record actual changed source files and generated asset paths in `files_changed`. Set status to `needs_verification` only when every pending prompt was processed. Never set `verified`, counts, percentages, or overall status.
6. If no prompts are pending, record that evidence in the task diagnostics and hand off as `needs_verification`; the Orchestrator independently verifies whether the repository has no remaining prompts and whether the task's scope is satisfied. Do not create arbitrary images unrelated to repository prompts.


## Homepage theme continuity
Read `sdocs/HOMEPAGE_DASHBOARD_HELP_BUDDY_BUILD_CONTRACT.md` when processing homepage/dashboard visuals. Maintain the same blue holographic identity in both pale blue/silver Daytime and deep navy/electric blue Nighttime treatments. Generate supporting visuals with sufficient tonal variants/contrast for both themes; do not bake UI text, navigation, stock values, clock text or news headlines into images. Keep visual assets subordinate to readable live interface data.
